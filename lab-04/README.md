# Lab 04 — Форма керування

Рівень: **Advanced** (Standard + `JC`/`JNC` + точка зупину `b <addr>`).

## Збірка й перевірка

```
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O2 ember.cpp -o ember
bash tests/lab04.sh        # 15 перевірок, усі мають бути ok
./ember                    # REPL; help — список команд
```

## Що змінилось у цій лабі

| Було | Стало |
| ---- | ----- |
| `step` обробляв частину опкодів, решту ігнорував | повний `switch (op)`; `default:` → `fault("unknown opcode 0x.. at PC=0x....")`, машина зупиняється |
| стрибків не було | `JMP 0x30`, `JZ 0x31`, `JNZ 0x32`, `JC 0x33`, `JNC 0x34` |
| `CMP` не було | `CMP A,B 0x1A`: рахує `A-B`, ставить `Z N C`, результат викидає |
| `run` міг крутитись вічно | ліміт `STEP_LIMIT = 100000`, див. нижче |
| — | команди `find <lo> <hi> <byte>`, `b <addr>`, `trace on|off` |

### Правило стрибка

У `step` змінна `next` спершу дорівнює `PC + 1`, кожен `imm8`/`imm16` посуває її далі, і лише
наприкінці `cpu.pc = next`. Стрибок, що **спрацював**, просто перезаписує `next = addr`.
Тому `PC` ніколи не отримує «адреса + 3»: розмір додається до *старого* `PC` ще до того, як
стрибок його перебиває. Тест `JMP не додає розмір`: `JMP 0x0005` з адреси 0 → `PC=0005`, а не `0008`.

### Ліміт кроків

`run` робить не більше `100000` інструкцій. Коли ліміт вичерпано, машина **зупиняється з помилкою**
`error: step limit (100000) exceeded, PC=0x....`, а не повисає. Перевірка: `JMP 0x0000` з адреси 0.
Після помилки стан (регістри, пам'ять) лишається для огляду; продовжити можна лише через `reset`.

### Невідомі опкоди

«Відомий» означає «додано в ISA до цієї лаби включно». `OUTS`, екран, стек, `ALLOC`, `MUL` з
лаб 5–7 тут ще невідомі й дадуть помилку. Саме так і треба: тихий `NOP` для сміття ховає баг,
а помилка з адресою показує його одразу.

### Прапорці (нагадування, бо це джерело багів)

`LOAD`/`LOADI`/`MOV`/`LOADH`/`INCH`/`HLOW` прапорці **не чіпають**. `JZ` читає те, що лишила
остання інструкція ALU або `CMP`. Тест `LOADI не чіпає Z`.

## 1. Зворотний відлік

### Лістинг (з колонкою адрес)

```
адр.  байти       текст
0000  20 03       LOADI A, 3
0002  03          loop:  OUTN
0003  19                 DEC A
0004  32 02 00           JNZ loop      ; операнд 0x0002, молодший байт уперед
0007  00                 HALT
```

Вивід: `3 2 1 ` (11 кроків). Збігається з ISA.uk.md §9.

### Те саме на C++

```cpp
int a = 3;
do {
    std::cout << a << ' ';   // OUTN
    --a;                     // DEC A, виставляє Z
} while (a != 0);            // JNZ loop
```

Це саме `do … while`, а не `while`: тіло виконується до перевірки (`JNZ` стоїть після `DEC`).
`while (a != 0)` для `a == 3` дало б той самий вивід, але для `a == 0` не надрукувало б нічого,
тоді як програма з `ember` надрукувала б `0` і пішла б у цикл на 255 кроків.

### Трасування (`trace on`, `run`)

`PC` — адреса виконаної інструкції. `A`, `Z` — стан **після** неї.

| # | PC   | інструкція    | A | Z | наступний PC | вивід |
|---|------|---------------|---|---|--------------|-------|
| 1 | 0000 | LOADI A,3     | 3 | 0 | 0002 |     |
| 2 | 0002 | OUTN          | 3 | 0 | 0003 | `3 ` |
| 3 | 0003 | DEC A         | 2 | 0 | 0004 |     |
| 4 | 0004 | JNZ 0x0002    | 2 | 0 | **0002** (стрибнув) | |
| 5 | 0002 | OUTN          | 2 | 0 | 0003 | `2 ` |
| 6 | 0003 | DEC A         | 1 | 0 | 0004 |     |
| 7 | 0004 | JNZ 0x0002    | 1 | 0 | **0002** (стрибнув) | |
| 8 | 0002 | OUTN          | 1 | 0 | 0003 | `1 ` |
| 9 | 0003 | DEC A         | 0 | **1** | 0004 | |
| 10 | 0004 | JNZ 0x0002   | 0 | 1 | **0007** (не стрибнув, `PC+3`) | |
| 11 | 0007 | HALT         | 0 | 1 | 0008 | |

Форма одна, записів два: `JNZ` на кроках 4 і 7 — це «умова `a != 0` істинна, повертаємось»;
на кроці 10 `Z=1`, умова хибна, `PC` просто йде далі на `+3`.

## 2. Лінійний пошук, версія C++

```cpp
// перше i у [lo, hi), де mem[i] == needle; промах → hi
std::uint16_t find(const Memory& mem, std::uint16_t lo, std::uint16_t hi, Byte needle) {
    for (std::uint16_t i = lo; i < hi; ++i) {
        if (mem_get(mem, i) == needle) return i;
    }
    return hi;
}
```

Команда: `find <lo> <hi> <byte>`. Промах — `hi`, і REPL друкує `not found` (бо `hi` лежить
поза діапазоном, а отже не може бути знайденою адресою).

```
> set 0x800 0x10 0x20 0x30 0x41
> find 0x800 0x808 0x41
found at 0x0803
> find 0x800 0x808 0x99
not found
```

## 3. Лінійний пошук, програма всередині `ember`

Шукає `0x41` у восьми байтах `0x800..0x807`. **Знайшла** → друкує індекс від початку ділянки
(`OUTN`). **Не знайшла** → друкує символ `-`.

### Моє рішення двох відкритих питань

* **Як цикл дізнається, що дійшов до `hi`.** `H` — 16-бітний, а порівнювати вміємо лише 8-бітні
  `A`/`B`. `0x800` має молодший байт `0x00`, тому `HLOW` (`A = H & 0xFF`) дає саме індекс `0..7`.
  Після порівняння з потрібним байтом роблю `HLOW`, `LOADI B,7`, `CMP`: якщо індекс уже 7,
  то елемент 7 щойно перевірили й далі йти нікуди → промах.
* **Як повідомити про промах.** Окремий вихід: друкую символ `-`. Індекс завжди `0..7`, тому
  число й `-` не можна сплутати. Альтернатива — друкувати 8 (як `find` повертає `hi`), але
  тоді «8» мовчки означає «нема», і це пастка для читача виводу.

Обмеження, яке я свідомо приймаю: програма покладається на `lo & 0xFF == 0`. Для довільного
`lo` індекс довелося б рахувати як `H_low − lo_low`, і при перенесенні через 256 це ламається.

### Лістинг (з колонкою адрес)

```
адр.  байти       текст
0000  28 00 08    LOADH H, 0x0800      ; i = lo
0003  29          loop:   LOAD  A, [H]     ; A = mem[i]
0004  21 41               LOADI B, 0x41    ; що шукаємо (перезавантажуємо: B ще знадобиться)
0006  1A                  CMP   A, B       ; Z=1, якщо рівні
0007  31 19 00            JZ    found      ; → 0x0019
000A  2D                  HLOW             ; A = i (молодший байт H)
000B  21 07               LOADI B, 7       ; останній індекс
000D  1A                  CMP   A, B
000E  31 15 00            JZ    miss       ; → 0x0015; i == 7 і не знайшли
0011  2B                  INCH             ; ++i
0012  30 03 00            JMP   loop       ; → 0x0003
0015  20 2D       miss:   LOADI A, '-'     ; 0x2D
0017  02                  OUT
0018  00                  HALT
0019  2D          found:  HLOW             ; A = індекс
001A  03                  OUTN
001B  00                  HALT
```

Байти для `set`:

```
set 0 0x28 0 8 0x29 0x21 0x41 0x1A 0x31 0x19 0 0x2D 0x21 7 0x1A 0x31 0x15 0 0x2B 0x30 3 0 0x20 0x2D 0x02 0 0x2D 0x03 0
```

### Прогони

| дані за `0x800`            | вивід | кроків |
| -------------------------- | ----- | ------ |
| `10 20 30 41 50 60 70 80`  | `3 `  | 38 |
| `41 ...`                   | `0 `  | 8  |
| `01 02 03 04 05 06 07 41`  | `7 `  | 78 |
| `01 02 03 04 05 06 07 08`  | `-`   | 82 |

| # | PC   | інструкція      | A  | B  | Z | наступний PC |
|---|------|-----------------|----|----|---|---|
| 1 | 0000 | LOADH H,0x0800  | 0  | 0  | 0 | 0003 |
| 2 | 0003 | LOAD A,[H]      | 16 | 0  | 0 | 0004 |

| 4 | 0006 | CMP A,B         | 16 | 65 | 0 | 0007 |
| 5 | 0007 | JZ 0x0019       | 16 | 65 | 0 | 000A (не стрибнув) |
| 6 | 000A | HLOW            | 0  | 65 | 0 | 000B |
| 7 | 000B | LOADI B,7       | 0  | 7  | 0 | 000D |
| 8 | 000D | CMP A,B         | 0  | 7  | 0 | 000E |
| 9 | 000E | JZ 0x0015       | 0  | 7  | 0 | 0011 (не стрибнув) |
| 10 | 0011 | INCH           | 0  | 7  | 0 | 0012 |
| 11 | 0012 | JMP 0x0003     | 0  | 7  | 0 | **0003** |

## 4. Advanced

* `JC addr16` (`0x33`) і `JNC addr16` (`0x34`) — стрибок за прапорцем `C`. Беззнакове
  порівняння: після `CMP A,B` `C=1` ⇔ `A < B`, тож `JC` це «A < B», `JNC` це «A ≥ B».
  Опкоди `0x33`/`0x34` уже зарезервовані в ISA як *opt*, тож таблицю не порушено.
* `b <addr>` — `run` до `PC == addr`; на самій адресі зупиняється **перед** її виконанням
  і не спрацьовує на першому кроці (інакше не вийти зі старту, коли `PC == addr`).
  Приклад: `b 7` на програмі відліку → `breakpoint at 0x0007`.

## 5. Відповіді на питання для захисту (коротко)

1. `while (a > 0) a = a - 1;` → `top: CMP-подібне порівняння; JZ end; DEC A; JMP top; end:`.
   `PC` ходить `top → … → JMP → top` скільки разів, скільки істинна умова, і один раз виходить на `end`.
2. `&&` — логічне, з коротким замиканням, дає `bool`. `&` — побітове. `1 && 2` істинне, `1 & 2` дорівнює `0`.
   `if (a & b)` замість `if (a && b)` компілюється, але для `a=1, b=2` дає хибу.
3. `x = 0` — вираз, значення якого `0`; у C++ це допустимий умовний вираз. Попередження ловить
   `-Wall` (clang: `-Wparentheses`; gcc: `-Wparentheses`), з `-Werror` стає помилкою.
4. Відлік — це `do … while` (перевірка після `DEC`). `for (a = 3; a != 0; --a)` і `while` теж
   впоралися б для `a ≥ 1`; різниця тільки для початкового `0`.
5. Коротке замикання захищає: `if (p && *p == 3)` не розіменує нульовий `p`. Небезпека: у
   `if (f() && g())` побічний ефект `g` може не статися.
6. Затінення: внутрішня коробка з `x` ховає зовнішню, поки не закрито `{ }`. `static int c`
   живе до кінця програми, але ім'я видно лише в блоці: після виходу з блока значення ще
   існує, просто звернутись до нього за іменем уже не можна.
7. Якби `JMP` додав ще `+3`, `JMP 0x0002` потрапив би на `0x0005`, і цикл «з'їдав» би 3 байти
   щоразу: адреси перестали б збігатися з тими, що в лістингу.
8. `SUB` ще й записує результат у `A`, знищуючи значення, яке потрібне далі. `CMP` порівнює, нічого не псуючи.
